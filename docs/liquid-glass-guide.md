# EasyMint Mobile 液态玻璃解析与实现指导

更新于 2026 年 11 月 5 日。适用于聊天输入卡、外观切换选中块，以及聊天顶部的磨砂覆盖层。实现与参数以当前源码为准。

## 已确认的视觉经验

**左右边缘使用极细暗线，上下边缘使用同样细的亮线，可以在亮色和暗色背景之间形成互补。** 亮色背景中，左右暗线帮助辨认轮廓和侧面厚度。暗色背景中，上下亮线更容易提供轮廓和受光线索。同一套轮廓同时保留两种对比关系，可以减少切换主题后边缘消失的情况。

这是本次用户在 Android 真机上比较多个版本后认可的设计经验。它适合当前输入卡的形状与背景，移植到其他尺寸、背景和设备时应重新观察强度。

液态感还来自背景像素经过边缘时的连续变化。文字、细线或色块滚到玻璃边缘时，应逐渐弯曲、压缩、拉伸，再平滑进入中心区域。静态的轮廓光帮助识别材质，连续的背景折射提供水滴般的动态观感。

## 观察 iOS 参考时关注什么

用户提供的 Dock 和 App 资源库截图中，同样的玻璃形状会随背后内容呈现不同的颜色和边缘强弱。可以观察到以下关系。

- 中心保留背景色彩与明暗结构，边缘承担更集中的扭曲与光影变化。
- 轮廓附近存在很窄的亮暗过渡，圆角把直边连续连接起来。
- 倒角带会混入背景颜色，亮边可能偏蓝、暖白或其他环境色。
- 背景接近纯色时变化较轻，经过文字、细线和明显色块时更容易看出折射。
- 图标、文字等前景内容保持清晰，背景采样层承担折射与模糊。

这些是截图的视觉观察与本项目的近似实现方向。Apple 的具体材质算法和动态表现需要另行验证，本文的公式对应 EasyMint Mobile 当前实现。

## 分层渲染结构

聊天页的合成顺序为背景与消息、玻璃背景、输入文字与交互控件。

| 层 | 本项目中的内容 | 实现要求 |
| --- | --- | --- |
| 背景与消息 | 环境渐变、聊天正文、表格、消息气泡 | 作为可持续更新的采样目标 |
| 玻璃背景 | 折射、少量模糊、背景取色、色散、轮廓光影 | 所有像素处理限定在这一层 |
| 前景内容 | 输入文字、图标、发送按钮、滑块标签 | 清晰绘制，保留正常点击与输入 |

Android 光学路径使用本地 Expo 模块 `MintLens`。`LensView` 把指定原生目标视图录入带留边的 `RenderNode`，再通过 `RuntimeShader` 与 `RenderEffect` 绘制材质。这样玻璃能读取真实聊天内容的位置和颜色。

## 形状与曲面

圆角矩形使用有符号距离场 SDF。每个像素到边界的距离决定该像素属于中心、倒角还是轮廓。当前约定内部距离为负，边界为零。

设玻璃尺寸为 `size`，圆角为 `radius`，像素位置为 `p`。

```glsl
q = abs(p - size * 0.5) - size * 0.5 + radius;
d = length(max(q, 0)) + min(max(q.x, q.y), 0) - radius;
depth = max(-d, 0);
```

形状、曲面法线、色散衰减、细边权重和轮廓遮罩共用这套距离关系。圆角附近的方向使用圆角距离场的连续外法线，避免分别绘制四条边造成接缝。

当前高度场使用圆滑弧形过渡，在中心进入恒定高度。

```glsl
localWidth = refractionWidth * (1 + 0.18 * lateralInfluence);
t = clamp(depth / localWidth, 0, 1);
height = refractionWidth * 0.48 * sqrt(max(0, 1 - (1 - t) * (1 - t)));
```

左右折射带按外法线 X 分量的平方逐渐增宽，直边处最大增加 18%，在圆角处连续过渡。高度平台仍使用全局 `refractionWidth * 0.48`，中心保持平整。

法线由高度场的中心差分得到，采样步长为 `localWidth * 0.152`。在 Android 的屏幕坐标中，X 向右、Y 向下，法线为 `normalize(vec3(-gradient, 1))`。移植网页着色器时要明确 Y 轴约定。

当前 SDF 遮罩在边界附近用约 1.5 个物理像素完成平滑过渡。原生 View 的圆角裁切与着色器遮罩需要同时对齐。

## 主折射与边缘额外折射

前表面使用高度场法线，背面使用平面法线。光路依次经过空气、玻璃、空气，再向背景位置投射。折射率基准为 `1.46`，玻璃厚度来自高度场。

中心采样坐标相对中心缩至 `98.8%`，产生轻微放大。接近倒角时，采样逐渐转为双界面光路结果。切换权重使用 `smoothstep`，减少背景像素突然跳位的情况。

边缘额外折射集中在折射带最外侧的 `40%` 范围内。

```glsl
rimDepth = depth / localWidth;
rimLens = 1 - smoothstep(0, 0.40, rimDepth);
rimOffset = -bendDirection * bevel * 0.13 * (1 + 0.12 * lateralInfluence)
          * rimLens * rimLens
          * ((ior - 1) / 0.46);
```

该偏移叠加到原有光路上，在向内结束的位置平滑归零。调节时应保持位置和变化速度连续。验收重点是文字或细线缓慢经过边缘时，变形能连续进入、连续退出。

## 左右暗边与上下亮边

两组细边使用同一条窄轮廓曲线，中心位于轮廓内约 `0.40 dp`。宽度参数为 `max(0.30 dp, 0.75 物理像素)`。实际可见宽度还受设备像素密度、透明度和抗锯齿影响。

设距离场外法线为 `outward`。

```glsl
profile = exp(-lateralDistance * lateralDistance);
lateralWeight = pow(abs(outward.x), 4);
horizontalWeight = pow(abs(outward.y), 4);
```

左右暗边按 `profile * lateralWeight * 0.16` 压低当前颜色。上下亮边按 `profile * horizontalWeight * 0.14`，向相同透明度的白色混合。亮边计算保留预乘透明度约定。

圆角处，两个方向的权重连续变化。例如方向约为 45 度时，两组权重各约为 `0.25`，轮廓会自然减弱并衔接。细边参数适合小步调整，明显加宽或加重后容易产生包边感。

这组主题互补的细轮廓，与背景自适应倒角光影分开控制。调整折射范围时，可以保持轮廓宽度稳定。

## 背景自适应光影与染色

倒角在法线方向的内外两侧读取背景，并沿切线取邻近样本做加权平均。这样可以降低单个文字像素对光影的干扰。

当前用背景亮度及内外亮度差调节光影。

- 亮度使用 `0.2126 R + 0.7152 G + 0.0722 B`。
- 内外亮度差经过 `smoothstep(0.015, 0.18, difference)` 得到局部对比度。
- 边缘活动强度为 `0.24 + 0.76 * localContrast`，纯色区域保留较轻的轮廓，内容复杂区域增加变化。
- 邻近背景偏暗时更容易产生亮边线索，邻近背景偏亮时更容易产生暗边线索。
- 倒角颜色混入附近环境色，随内容滚动持续更新。

直接按亮度切换明暗，仍可能在部分背景上呈现内凹感。本次尝试的另一版凸面定向高光与外侧软阴影未获用户认可，当前保留背景自适应版本，并配合用户认可的左右暗边、上下亮边。凸起感需要结合实际背景持续比较。

输入卡采用轻微黑色染色。亮色主题的 `liquidClearFill` 为黑色 `4.5%`，暗色主题为黑色 `3.5%`。染色帮助保留背景颜色，抑制整面发白。颜色统一从主题 token 读取。

## 边缘色散

当前分别使用 `IOR - dispersion`、`IOR`、`IOR + dispersion` 采样 R、G、B 通道。色散只在边缘逐渐增强。

```glsl
rimDispersion = 1 - smoothstep(0, 0.45, refractionT);
dispersion = edgeSupport * 0.003 + rimDispersion * 0.001;
```

最外侧的折射率差最大约为 `0.004`，向中心逐渐减小。小幅分离能增加介质感，调大后应重点检查文字附近是否出现抢眼的彩边。

## 当前参数基线

以下参数记录本次实现状态，后续调整以源码和真机结果为准。

| 参数 | 当前值或关系 | 调节影响 |
| --- | --- | --- |
| 输入卡圆角 | `24 dp` | 圆角曲率与裁切轮廓 |
| 光影倒角宽度 | `bevel = height * (0.025 / 0.244)` | 侧面光影的基本尺度 |
| 折射带宽度 | `refractionWidth = bevel * 1.32` | 向中心延伸的范围 |
| 左右局部折射宽度 | 基础宽度乘以 `1 + 0.18 * lateralInfluence` | 侧面更宽的圆滑过渡，圆角连续衰减 |
| 曲面高度比例 | `0.48 * refractionWidth` | 法线倾斜及玻璃内光程 |
| 背景传播距离 | `0.86 * bevel * (1 + 0.28 * lateralInfluence)` | 双界面折射后的背景偏移 |
| 额外边缘偏移 | `0.13 * bevel * (1 + 0.12 * lateralInfluence)`，按边缘权重衰减 | 最外侧的水滴透镜感 |
| 左右暗线强度 | `0.16` | 亮背景中的轮廓对比 |
| 上下亮线混合强度 | `0.14` | 暗背景中的轮廓对比 |
| 光学背景模糊 | `0.65 dp` | 背景细节与通透程度 |
| 顶部磨砂模糊 | `8 dp` | 标题和状态栏下方内容的可读性分离 |
| 背景采样留边 | `26 dp` | 录制原生背景时的扩展范围 |

`Composer` 传给 `Glass` 的 `intensity` 控制 BlurView 回退路径。原生光学路径的模糊参数在 `LensModule.kt` 中设置，调参时应分别确认实际走到的路径。

## 黑边故障的排查结论

本次曾出现输入卡最底部的一条硬黑边。应区分这类横向接缝与沿圆角变化的厚度阴影。

真机分层测试得到以下结果。

| 隔离条件 | 结果 |
| --- | --- |
| 用纯色替代光学输出 | 黑边消失 |
| 保留玻璃效果，关闭底部渐隐 | 黑边仍在 |
| 只显示原始背景采样 | 黑边消失 |
| 只保留折射采样 | 黑边消失 |
| 修正倒角环境取色的边界与透明度处理 | 完整材质中的硬黑边消失 |

因此，本次修复针对倒角环境取色。Android 原生图层的实际可采样范围受裁切影响，扩展 `RenderNode` 后仍要约束局部环境取色坐标。透明边界像素的 RGB 在直接混色时可能形成暗缝。

当前 `backgroundColorAt` 将邻域取色限制在有效表面范围内，对非零 alpha 样本解预乘，并在样本接近透明时回退到有效背景颜色。预乘颜色、直通颜色和输出 alpha 必须保持一致。

修改相关代码时保留以下检查。

1. 在纯色背景下定位接缝的实际位置，区分最底部横线与侧面倒角。
2. 分别隔离背景、折射、环境取色和光影，记录哪一步出现异常。
3. 同时核对捕获坐标、采样范围、透明度及 SDF 遮罩。
4. 恢复完整效果后检查静止和滚动，确认修复没有误删正常厚度光影。

## 顶部覆盖层与状态栏

聊天页把消息列表延伸到标题和系统状态栏下方。磨砂层覆盖顶部安全区和标题栏，前景标题按安全区内边距布局。

- `App.tsx` 在聊天页把顶部安全区交给 `ChatScreen` 管理。
- 顶部覆盖层的 `paddingTop` 使用 `insets.top`。
- 消息列表的顶部留白使用 `HEADER_HEIGHT + insets.top`，保证滚到最早消息时可以完整阅读。
- 背景对齐窗口坐标，减少状态栏、标题栏和正文之间的渐变接缝。
- 顶部原生光学半径设为零，使用磨砂背景路径。

底部渐隐目前保留在屏幕底端的窄带内。本次黑边排查已验证，关闭它不能消除上述采样故障。

## 调整顺序与验收方法

先固定一个已认可的版本，逐项改变参数，并用同一段聊天内容、相同滚动位置进行比较。

| 调整目标 | 优先调整 | 验收重点 |
| --- | --- | --- |
| 更强的液态感 | 折射带宽度、额外边缘偏移 | 像素经过边缘时连续弯曲和恢复 |
| 更清楚的材质轮廓 | 左右暗线、上下亮线的强度 | 亮暗主题中均可辨认，宽度保持细窄 |
| 更自然的背景适应 | 邻域取色范围、局部对比权重 | 纯色安静，复杂背景变化可见 |
| 更通透 | 模糊量、黑色染色 | 保留背景层次，同时检查输入文字可读性 |
| 更明显的介质色散 | 边缘 IOR 差 | 彩边轻微并向中心平滑衰减 |
| 修复异常黑缝 | 捕获边界、预乘透明度、SDF 遮罩 | 精确定位接缝，使用分层测试 |

最少覆盖亮色与暗色、纯色背景、密集文字、表格细线、彩色消息块、缓慢滚动、快速滚动和键盘展开。重点观察左右边到上下边的圆角过渡，以及滚动停下后是否残留固定光带或硬接缝。

## 平台能力与性能边界

Android 13 及以上且 `MintLens` 模块可用时进入原生 RuntimeShader 光学路径。Android 12 走支持背景目标的 BlurView 回退。更早的 Android 版本按当前 `dimezisBlurViewSdk31Plus` 配置回退为半透明材质和装饰层。iOS 当前走 BlurView 与容器装饰层，完整的本地 Android 光学实现需要另行适配到 iOS。

当前原生视图使用 `postInvalidateDelayed(33)` 请求持续更新，并在卸载时释放显示列表。实际帧率还取决于消息复杂度、设备 GPU 和背景录制成本。大规模复用前应测量长会话滚动帧耗时、GPU/内存占用和持续运行耗电。当前真机视觉验证不能替代多机型性能验证。

网页预览与 App 分别使用 WebGL/Three.js 和 Android RenderNode/AGSL。移植时逐项对应几何尺度、法线步长、背景传播距离、采样范围、透明度和轮廓遮罩，再对比画面。构建通过后仍需进行真机视觉验收。
