# EasyMint Mobile 液态玻璃解析与实现指导

更新于 2026 年 11 月 6 日。聊天输入卡及首页/会话列表的圆形悬浮按钮共用水滴式液态玻璃参数；外观切换、会话长按菜单、聊天顶部使用磨砂玻璃。

## 已确认的视觉经验

**左右边缘使用极细暗线，上下边缘使用同样细的亮线，可以在亮色和暗色背景之间形成互补。** 亮色背景中，左右暗线帮助辨认轮廓和侧面厚度。暗色背景中，上下亮线更容易提供轮廓和受光线索。同一套轮廓同时保留两种对比关系，可以减少切换主题后边缘消失的情况。

这是本次用户在 Android 真机上比较多个版本后认可的设计经验。它适合当前输入卡的形状与背景，移植到其他尺寸、背景和设备时应重新观察强度。

液态感还来自背景像素经过边缘时的连续变化。文字、细线或色块滚到玻璃边缘时，应逐渐弯曲、压缩、拉伸，再平滑进入中心区域。静态的轮廓光帮助识别材质，连续的背景折射提供水滴般的动态观感。

## 观察 iOS 参考时关注什么

用户提供的 Dock 和 App 资源库截图中，同样的玻璃形状会随背后内容呈现不同的颜色和边缘强弱。可以观察到以下关系。

- 中心保留背景色彩与明暗结构，边缘承担更集中的扭曲与光影变化。
- 轮廓附近存在很窄的亮暗过渡，圆角把直边连续连接起来。
- 倒角带会混入背景颜色，亮边可能偏蓝、暖白或其他环境色。
- 背景接近纯色时变化较轻，经过文字、细线和明显色块时更容易看出折射。
- 图标、文字等前景内容保持清晰，背景采样层承担折射与模糊。

这些是截图的视觉观察与本项目的近似实现方向。Apple 的具体材质算法和动态表现需要另行验证，本文的公式对应 EasyMint Mobile 当前实现。

## 分层、曲面与折射

背景与消息先绘制到独立采样目标，材质层处理其像素，输入文字和按钮最后作为清晰的原生控件绘制。采样目标不能包含玻璃自身，避免递归反馈。聊天输入卡按键盘、安全区、内容实际布局，演示 JSON 的位置不覆盖业务布局。

圆角矩形 SDF 内部为负、边界为零。高度场采用圆弧 `height = refractionWidth * heightRatio * sqrt(1 - (1 - t)^2)`，其中 `t = clamp(depth/localWidth, 0, 1)`。平台中心高度恒定，法线通过高度场的中心差分取得。左右带宽由外法线 X 分量平方平滑增强，圆角共用连续方向，避免四边分别绘制造成接缝。

光路经过空气→玻璃→空气，折射率 1.5。主折射由高度和光程计算；额外水滴边缘折射只在外缘平滑增强。主折射、额外折射、色散分别衰减，中心不应出现突然的位移分界。`faceScale=1` 保持中心尺度。`sideWidth=1.3`、`sideTravel=1.3`、`sideRim=1.22` 为左右圆润感提供更宽且更强的折射。

左右细暗边与上下细亮边共用距离场轮廓，方向权重分别使用外法线 X/Y 分量的四次方，圆角处连续混合。环境色和明暗来自实际背景邻域，不靠固定左上亮、右下暗的厚描边。

## 黑边与采样故障定位

先区分正常窄轮廓阴影与采样故障。硬直黑边、边缘外侧矩形带、拖动后固定的模糊条带，应检查捕获与合成，不应先删正常厚度阴影。

Android 捕获区域在实际控件四周外扩 26 dp；RenderNode 对齐屏幕坐标，最终输出裁回控件范围。邻域采样必须限制到有效背景范围，混色前解除预乘透明度并处理接近零的 alpha，避免透明像素中的黑 RGB 混入材质。

Web 捕获完整滚动源，并用当前屏幕位置和滚动量映射采样坐标；异步捕获带版本号，过期结果不能覆盖新布局。CSS 圆形与变换由 foreignObject 路径光栅化。多个玻璃共用 GPU 时，每块先快照成独立 ImageBitmap，再复用画布，避免尺寸变化串帧。超出源范围取场景底色，不能把首尾纹理行拉成直线。

## 磨砂玻璃与功能提示

磨砂层使用普通模糊和主题半透明染色，不执行边缘折射。原生 `radius=0` 选择这条路径，容器仍按实际圆角裁切。悬浮按钮和菜单的采样目标与控件是兄弟层，避免自采样；Modal 需要从原 Activity 查找背景视图。首页/会话列表的悬浮按钮复用输入卡的无色/轻黑染色与光学参数，按 58 dp 圆形几何自动计算倒角宽度，保留淡绿图标对比。两个按钮距安全区右侧 28 dp、底部 34 dp。

列表背景虽然在独立采样目标内绘制，但其渐变坐标必须对齐全窗口：向上扩展 top inset、向下扩展 bottom inset，避免安全区边界处出现一条色差接缝。

输入卡圆圈是上下文用量提示，数据来自远程会话状态，不是未接入按钮。提示框放在输入卡层级，不能嵌在 30 dp 图标容器内让文字变成省略号；数据未知时只说明未知窗口/使用率，不虚构百分比。

## 平台边界与验收

Android 13/API 33 以上使用 RuntimeShader；旧 Android 使用模糊回退。iOS 26+ 通过 `SystemGlass.ios.tsx` 使用 expo-glass-effect 原生 `GlassView`（clear），明暗由 App 的 effectiveMode 控制；同时检查 API 和编译配置能力。旧 iOS 使用磨砂 BlurView；开启「降低透明度」时使用不透明主题面。iOS 采用苹果系统材质，未移植自定义 Metal 光学公式，不保证与 JSON 参数逐像素一致。

WebGL2 与 Android 共用曲面和光学公式，但背景捕获、字体光栅化、像素密度与模糊核不同。使用亮/暗、纯色、网格、密集文字和彩色图案，观察慢速滚动经过边缘时的连续拉伸与恢复；检查圆角接缝、输入和手势、键盘切换、透明边界及长时间性能。不要仅凭静态截图宣称逐像素一致。

## 聊天阅读区的材质协调

思考、工具输出、系统通知和代码块使用 `chatPanel/chatInset/chatCode/chatDivider` 中性半透明 token；行内代码仅轻微衬底，避免旧米色/实灰色块打断环境背景。代码块只由最外层上底色，内部滚动区透明，避免半透明重复叠加。用户气泡、diff 增删和成功/失败等语义色保留。

系统结果通知的原始协议继续使用 `⏺` 进行解析；显示时标题栏用真实圆形 View，正文用不带 emoji 表现的 `●`。不要直接显示 U+23FA，它在手机上可能由彩色 emoji 字体画成带底板的按钮，覆盖指定状态色。

## iOS 键盘与底部安全区

iOS 只使用 App 根节点的一份全屏环境背景。聊天区的 BlurTargetView 保持透明，不绘制第二份环境渐变，也不叠加 Android 的底部渐隐涂层。KeyboardAvoidingView 缩短消息区时，根背景不改变坐标与高度，因此输入卡背后、键盘上方以及底部安全区保持连续。iOS 原生玻璃直接读取实际背后的背景和消息，不需要在捕获目标内复制环境色。Android 的自定义捕获背景和渐隐保留。输入框 keyboardAppearance 明确跟随 effectiveMode。
